# Locale

Review multilingual releases without losing track of missing or outdated screenshots.

**Bounded, local-only demonstration.** Rust owns validation, coverage, evidence fingerprints, review decisions and JSON reporting. Capacity checks refuse a decision atomically if its candidate snapshot could no longer be exported. A small framework-free browser UI loads Rust as WebAssembly. The supplied **Vale / Autumn release** project, UI captures, reviewers and review notes are entirely synthetic.

## Try the demo

[Open the Locale demo](https://project-refiy.vercel.app/) with the bundled synthetic **Vale / Autumn release**. No account or setup is needed.

For a step-by-step exercise with expected report fields and limitations, see the [first-use guide](docs/FIRST-USE.md).

1. Explore **All views** and **Needs attention** to see missing, outdated and unverified captures.
2. Open an available capture to inspect its image and declared metadata, then choose **Close review**.
3. Choose **Export report** and inspect the JSON locally. Incomplete coverage remains visible; this is not translation, visual-quality or accessibility certification.

Work stays in this tab and clears on reload. Export before leaving. To use your own synthetic inputs or change the code, see [Run / build](#run--build) and [Manifest and import workflow](#manifest-and-import-workflow).

Export preserves a review record for reference, without image bytes. Exported reports cannot be imported to resume a session. Keep your original manifest and image files if you want to review them again; importing them starts a new session with no previous decisions.

## Implemented

- An explicit expected locale × screen × state × configuration × text-size × appearance matrix. Coverage is never inferred from the captures that happened to arrive.
- Strict schema-v1 manifest import and optional local PNG/JPEG image attachment. Unknown JSON fields, duplicate configurations, duplicate image names, paths/remote URLs, unexpected files and oversized inputs are rejected.
- Missing captures, outdated build/catalog identities, absent provenance metadata, unavailable image bytes and declared SHA-256 mismatches remain visible and block approval.
- Thumbnail matrix, status/locale/search filters, no-results reset, side-by-side capture inspection, intrinsic-size viewing (one decoded image pixel per CSS pixel), keyboard-accessible modal close and mobile review layout.
- Human approval, change requests and comments. Changes require a note. Reviewer name is required. Duplicate repeated decisions are idempotent.
- SHA-256 review binding includes the target build/catalog, full expected identity, all declared capture metadata and locally loaded image hash. Changed evidence invalidates the latest decision; stale UI revisions cannot save a decision.
- JSON report export with complete/incomplete coverage, current evidence bindings, historical decisions and explicit uncertainties. No image bytes are exported.
- The same Rust core runs as a native stdin/stdout CLI or in WebAssembly. No network calls, clock, filesystem or host dependencies in the core library.

## Honest boundaries

This is **not** automatic clipping, accessibility, visual-quality or translation certification. Captures are generated by existing desktop/CI tools. The browser hashes the bytes it loaded, but metadata such as build, locale, catalog version and capture time is declared by the importer. A catalog hash is provenance metadata, not proof the running application rendered that catalog.

Reviewer names and timestamps are unauthenticated. An evidence fingerprint is **not a digital signature**. “Approved” means a locally recorded human decision matches the current declared evidence. Reports can be modified by their holder. This local demo is not a tamper-evident multi-party audit system.

Review state and local image URLs live **only in tab memory** and are lost on reload or closing the tab. Export before leaving. There is no upload API, account, cross-device synchronization, backend, service worker, analytics, remote image fetch, OCR or shared-server claim. Opening the demo downloads its static app and synthetic fixtures; user-selected files are processed locally.

Side-by-side reference captures are another declared locale from this release, not certified baselines or automated diffs. Long labels and Arabic fixture text are synthetic examples, not professionally verified translations.

Future self-hosted work includes authenticated reviewers, synchronized durable storage, capture adapters, retention, release creation and review assignment. This demo accepts one normalized manifest format, not arbitrary Xcode/xcresult, translation catalogs or screenshot archives. Product differentiation and real-team demand remain unvalidated; compare the workflow against configured VRT, Allure, Percy/Applitools and TMS screenshot workflows.

## Run / build

Requirements: Rust **1.99.0**, pinned with the WASM target and formatting/lint components in `rust-toolchain.toml` (edition 2024), `wasm32-unknown-unknown` target, a modern browser with WebAssembly/Web Crypto/CreateImageBitmap, and a static HTTP server. JavaScript has no third-party runtime dependencies.

```sh
rustup target add wasm32-unknown-unknown
bash scripts/build.sh
python -m http.server 8763 --directory web
# Open http://localhost:8763
```

The committed `web/locale_review.wasm` supports static deployment without a Rust toolchain at deploy time. `scripts/build.sh` remaps checkout, Cargo-cache and Rust-toolchain paths to portable prefixes so machine-specific filesystem paths are not embedded in the artifact. Use this script for distributable builds. Vercel explicitly selects no framework, disables installation, and runs only `node scripts/verify-build.mjs`, which checks the prebuilt WASM, static fixtures and served license texts. `vercel.json` serves `web` with restrictive CSP, no framing, no camera/microphone/location permissions and no-referrer headers. No paid services are required. Deployment must still pass the browser acceptance checks.

Native processing accepts an operation envelope on stdin:

```sh
python -c 'import json; print(json.dumps({"op":"audit", "project":json.load(open("tests/fixture.json"))}))' | cargo run --quiet
```

Request operations: `audit {project}`, `decide {project,slot,expected_fingerprint,expected_revision,decision,reviewer,comment,at}`, and `export {project}`. Each returned decision includes the updated project and audit; callers must use the returned snapshot for the next operation. The public functions `validate`, `audit` and `process` are also usable from Rust. Native requests are bounded before JSON parsing.

## Manifest and import workflow

1. Download `web/sample-manifest.json` as a schema example.
2. Declare the project/release target build, lowercase 64-hex catalog hash and all required configurations in `expected`.
3. Add capture records with an exact `slot`, declared `build`, `catalog_hash`, UTC `captured_at` (`YYYY-MM-DDTHH:mm:ss[.sss]Z`), local PNG/JPEG basename `image`, and optional lowercase hex `sha256`.
4. Import the manifest and matching image files. A manifest-only import is allowed but its image-less captures remain unverified.
5. Review each current capture, giving a name and optional approval note or required change-request/comment note. Inspect metadata and pixels yourself.
6. Export JSON. Read it before sharing: filenames, reviewer names and comments may be sensitive.

No imported review history is trusted or loaded by the UI. A new manifest import starts a new session; cancel or failure keeps the current session unchanged. Attaching a replacement image within a session preserves review history and invalidates mismatched evidence. To update declared metadata, import a corrected manifest as a new session; the core additionally supports version changes through its project API and tests their invalidation behavior.

### Limits

- Manifest file: 512 KiB; core operation request: 1 MiB.
- Expected configurations / captures / attachments: 200 each; review events: 500.
- Image: 5 MiB, maximum side 8,000 pixels, maximum 12 megapixels.
- Session image bytes: 30 MiB; session image dimensions: 60 megapixels total.
- Project/build/release strings: 100 characters; slot identity parts and reviewer: 80; filenames: 128; comment: 1,500.
- Filenames are basenames only. PNG and JPEG bytes are inspected before bounded browser decode. SVG is not accepted. Image decoding uses the browser’s own decoder; the application does not claim to sanitize unsafe image codecs.
- Image processing uses a shared queue with at most one active dedicated worker and one pending job. Cancellation aborts local FileReader work and terminates the active image worker, rejects queued work and ignores late results. Replacements also check the original modal session and project revision. Unit tests exercise queue lifetime with injected workers; actual browser-decoder cleanup/performance is not claimed before browser QA.

## Verification

```sh
cargo test --locked
cargo clippy --all-targets -- -D warnings
node --check web/app.js
node scripts/wasm-tests.mjs
node scripts/capacity-tests.mjs
node scripts/image-pipeline-tests.mjs
node scripts/accessibility-static-tests.mjs
node scripts/verify-build.mjs
python scripts/browser-tests.py
```

The browser test runner is pinned in `requirements-browser.lock` (Python 3.12 tested, Playwright 1.62.0 and exact transitive versions). Set up an isolated environment with `python -m venv .venv`, activate it, run `python -m pip install -r requirements-browser.lock`, then `python -m playwright install chromium`. The script defaults to that version's bundled Chromium; `CHROMIUM_EXECUTABLE` may explicitly select another binary, which must be reported as a different verification environment. `LOCALE_BASE_URL` may target an authorized static preview. It serves only synthetic fixtures and local test inputs. These test-only dependencies are never installed during deployment. `evidence/QA.md` records exactly which stages ran, which did not and why. Do not treat existence of the browser script as a passing result. Browser automation is distinct from physical iOS/Android testing.

`evidence/source-sha256.txt` binds the reviewed local source set and built WASM. The manifest identifies the tested source and artifact set independently of Git commit labels.

## Accessibility scope

The UI uses one explicit light palette for either OS color-scheme preference; a dark theme is not implemented. Corrected status labels have calculated contrast from 6.285:1 to 6.66:1; supporting copy tested is at least 5.777:1. These are source-token calculations, not a blanket WCAG or screen-reader certification. Capture names expose device configuration, text size and appearance, scrollable image regions are focusable, and a polite live region inside the modal carries decision feedback. Browser/assistive-technology verification remains a separate gate.
